# CHANGELOG

このツールは**四度、独立した監査エージェントに攻撃されている。**
そのたびに穴が見つかり、塞ぎ、**塞いだ証拠を負の対照実験として `tests/` に残して**きた。

「検査が通った」を信じてよいのは、**検査器自身が壊れていないことを確認したときだけ**。
以下はその履歴である。**見つかった誤りを消さずに残すことが、この文書の目的。**

## v1.3.1 — 2026-09-05（4回目の監査：**見逃し**ではなく**偽 FAIL**）

4回目の監査（`audit_fable4`）では、素通り（偽陰性）は**1件も出なかった**。
139本の `.asc` を旧版と新版で変換して突き合わせ、差が出たのは4本だけで、
どれも「旧版が黙って捨てていた属性（`AC 10` / `tc=0.5` / `Rpar=0.001`）を
新版が保持するようになった」方向、つまり v1.3.0 の修正が効いている証拠だった。

代わりに出たのは**逆の欠陥**――無傷の図面を FAIL と言う偽陽性である。

### `asc2ngspice.py` が作ったデッキと照合すると、無傷の図面が FAIL した

`--check` のディレクティブ比較（v1.3.0 で追加）は、`.asc` が運んでいるカードを
入力デッキのカードと**逐語で**突き合わせていた。人が書いた `.cir` から
`net2asc.py` が図を描く向きでは、ディレクティブは逐語コピーなのでこれで正しい。

しかし**逆向き**――`.asc` と、その `.asc` から `asc2ngspice.py` が作ったデッキ――では
逐語ではない。`emit()` は次を行うからである：

```
.param a1=10 b1=1 c1=a1/b1   →  1カード1代入に分解
.param η=0.85                →  .param eta=0.85      （ギリシャ文字の音訳）
.tran 0 4m 0 20n startup     →  .tran 20n 4m 0 20n uic
                             ＋ .param pi=... を注入
                             ＋ .options 収束補助を注入
```

PSFB の3図面（`original` / `improved` / `sync_ct`）で測ると、**素子52個・ネット32本が
完全一致してもなお 30件**の「DIRECTIVE MISSING / ADDED」が出た。
読み手にはこれは「図面が壊れている」としか読めない。

**偽陽性は偽陰性と同じくらい有害である**：常に FAIL する検査は、いずれ読み飛ばされる。

→ 入力デッキが `asc2ngspice.py` の**生成物である場合に限り**（デッキ先頭の
`* generated by asc2ngspice.py from ...` で判定）、比較の両辺を**同じ翻訳器に通す**
――ラウンドトリップ・デッキと入力デッキを突き合わせる――ようにした。
書き換えは両辺に等しくかかって相殺し、順序は多重集合なので無関係になる。
人が書いたデッキ相手の逐語比較は**一行も変えていない**。

### 検査が骨抜きになっていないことの確認

緩めた側の修正なので、負の対照を先に用意した（`tests/a2n_dir_test.cir`、
セルフテストの「2c」）。生成デッキ相手でも次はすべて FAIL・exit 1 になる：

| 改竄 | 出るメッセージ |
|---|---|
| `.tran` の削除 | `DIRECTIVE MISSING FROM .asc (1 card(s)): .tran 1u 1m 0 1u uic` |
| 複数代入 `.param` から1個だけ削除 | `DIRECTIVE MISSING FROM .asc (1 card(s)): .param spare=3` |
| パラメータ値の改変 | `DIRECTIVE ADDED TO .asc (1 card(s)): .param eta=0.5` |
| カードの追加 | `DIRECTIVE ADDED TO .asc (1 card(s)): .ic v(mid)=7` |

むしろ**分解能は上がっている**：複数代入カードの中の1代入だけを消す改竄は、
逐語比較ではカード全体が「MISSING ＋ ADDED」の対で出るだけだったが、
いまは `.param spare=3` が消えたと名指しで出る。

修正前のコードにこの 2c を掛けると（1)の無傷 PASS と「値の改変」の2件が落ちる）
確かに不合格になる。**対照が対照として働いていることまで確認済み。**


### もう一つ：ngspice が読めない綴りを、PASS のまま持ち出していた（E1）

`.param η=0.85` は `eta` に音訳していたのに、**素子値の中の参照**は素通りしていた：

```
.param eta=0.85          ← 定義は音訳された
R1 in mid {1k*η}         ← 参照は音訳されていない
```

ngspice-41 で実行すると `Undefined parameter` / `Cannot compute substitute` で
**fatal error** になる。それでも `--check` は **PASS** と言っていた——比較の両辺が
同じ未翻訳の文字列を運ぶので、差として出ようがないからである。
**走らないデッキは PASS ではない。**

同じ場所で見つけた地雷をもう一つ潰した。ngspice-41 で実測すると：

| 綴り | ngspice が読む値 | 挙動 |
|---|---|---|
| `1u` | 1e-6 | 正常 |
| `1µ`（U+00B5 MICRO SIGN） | 1e-6 | 正常 |
| `1μ`（U+03BC ギリシャ文字μ） | **1.0** | `warning, can't find model '1μ'` だけ＝**黙って 10⁶ 倍** |

→ 音訳が曖昧でない2つだけを、**カード全体に一貫して**掛けるようにした
（`η`→`eta` はどこでも、`µ`/`μ`→`u` は**数字か小数点の直後＝倍率接尾辞のときだけ**）。
それ以外の非ASCII がカードに残った場合は、**当てずっぽうで訳さず `ERROR`** にする。
`net2asc.py` は抽出器の `ERROR` を検査失敗として扱うので、この種のデッキは
もう PASS のまま持ち出せない。

なお本プロジェクトの `.asc` 191 本を調べたところ、`µ`/`μ` は**1文字も無く**、
`η` は 40 箇所すべてが `.param` カードの中（定義と参照が同じカード群）だった。
**つまり実際に壊れていたデッキは無い。仕掛けられていたが踏んでいなかった罠である。**
負の対照はセルフテストの「2d」（`ngspice` があれば実機でも読ませる）。

回帰確認：`audit_fable4/rt/` の全49ケースを再実行し、判定が変わったのは
偽 FAIL だった7ケース（PSFB 3図面 × 2デッキ ＋ `p28`）**だけ**。
攻撃ケース（`atk1`〜`atk10`, `p1`〜`p30`）の FAIL / MISMATCH は**1件も減っていない**。
E1 の修正（抽出器側）でも 49 ケースの判定は**1件も動かなかった**。
`tests/selftest.sh` は 28/28 PASS（2c で5件、2d で4件を追加）。

## v1.3.0 — 2026-09-04（同日の独立**再**監査）

前回（v1.2.0）の指摘は「本当に直っている」と確認されたうえで、**新しく3つ**見つかった。
3つとも `VERIFY: PASS` / exit 0 で素通りしていた。証拠は `audit_fable3/`（`atk1`〜`atk10`）。

### 独立監査（3回目）で見つかった穴

**① `SYMATTR SpiceLine` の未消費キーと `SYMATTR Value2` を黙って捨てていた**

生成した `.asc` のコンデンサに 1 行足すだけで素通りした：

```
SYMATTR SpiceLine Rpar=0.001      ← LTspice ではこの C に 1 mΩ が並列に入る＝実質短絡
```

抵抗への `SpiceLine tc=0.5`、電圧源への `Value2 AC 10` も同じ。
LTspice が実際にネットリストへ書き出すのは

```
<素子名> <ノード…> <Value> <Value2> <SpiceLine> <SpiceLine2>
```

であるのに対し、`asc2ngspice.py` の `parse_spiceline()` は `rser`/`lser` だけを取り出し
（これは正しく明示素子へ展開していた）、**残りのキーを一つ残らず捨てて**いた。
`Value2` に至っては**一度も読んでいなかった**。
捨てられたものは抽出デッキに現れないので、**ラウンドトリップは原理的に見られなかった。**

→ 直したのは「`Rpar` を知る」ことではなく「**何も黙って捨てない**」という性質のほう。
- 消費しなかった `SpiceLine` のキーと `Value2` / `SpiceLine2` を**素子カードの尾部に
  そのまま付ける**。こうすると既存の値比較がそのまま拾う。付けた場合は WARNING を出す
  （LTspice は解釈するが ngspice が解釈するとは限らない）。
- それでも置き場所の無い `SYMATTR`（`SpiceModel` 等）は **ERROR にして FAIL** させる。
  `asc2ngspice.py` 単体でも終了コード 1 になる。
  *比較できないものを黙って比較対象から外すのは、存在しない検査カバレッジの主張である。*
- `rser`/`lser` の展開は従来どおり（`improved.asc` の 9 本の `SYMATTR SpiceLine Rser=...`
  で確認。**リポジトリ内 40 枚の `.asc` すべてで抽出結果は 1 バイトも変わらない**）。
- 負の対照：`tests/corrupt_E_spiceline.asc` / `corrupt_F_value2.asc` /
  `corrupt_J_unknownattr.asc`

**② `K` の結合係数を比較していなかった**

`!K1 L_conv L_ant {K_VALUE}` を `0.001` に書き換える＝**結合をほぼ 0 にする**改竄が素通りした。
`topology()` が `kmap[t[0]] = t[1:-1]` と書いており、**最後のトークン＝結合係数を意図的に
捨てて**、結合する相手だけを比べていたため。相手の入れ替えと `K` の削除は落ちていたので、
表向きは「`K` を検査している」ように見えていた。

→ `k_parts()` で名前・相手・係数に分け、係数を `normalise_value()`（素子値とまったく同じ
正規化）に通して比較する。braces 内に空白のある係数（`{k * 2}`）にも対応。
→ 負の対照：`tests/corrupt_G_kcoeff.asc`

**③ ディレクティブの存在を比較していなかった**

`!.tran` カードや `!.ic v(mid)=2` を `.asc` から削除しても素通りした。
**走らないデッキ／初期状態の違うデッキ**になるのに `VERIFY: PASS` / exit 0。
文書化されていた除外は「`.model`/`.param`/`.options` の**中身**は比べない」であって、
`.ic`/`.tran` の**削除**を許すとは書いていない。**実装のほうが文書より緩かった。**

→ `directive_set_check()` を追加。`.asc` が TEXT `!` として運んでいる `.xxx` カードの
**多重集合**を入力デッキと照合する。削除も追加も FAIL。

何をどう比べるかは意識的に選んである（詳細は `NET2ASC.md` 3.8 節）：

| 種類 | 比べ方 | 理由 |
|---|---|---|
| `.xxx` カードすべて | **内容**（多重集合・`normalise_value()`） | `net2asc.py` はディレクティブを `.asc` へ逐語的に写す。唯一の書き換え `_to_braces()` は `normalise_value()` が両側に同じ変換を掛けるので相殺される。5 デッキで実測（37/39/42/46/3 カード）して一致を確認 |
| `K` カード | ここでは比べない | 検査 2 の `kmap` が相手と係数を比べている（二重に落としても情報が増えない） |
| シンボルの無い素子カード（`B`/`E`/`G`/`F`/`H`） | ここでは比べない | `topology()` が素子として値まで比べている |
| `;` の TEXT 行 | 比べない | ディレクティブではなく、シミュレーションに影響しない |

**照合先をラウンドトリップ*デッキ*ではなく `.asc` にしたのが要点。** rt デッキは
`asc2ngspice.py` が `.tran` を書き換え・`.param` を並べ替え・`.options` を注入するので
比較に使えない。`.asc` を直接見た副作用として、
**`.model` / `.param` / `.options` の中身も比較できるようになった**
（検出可否表の #13 が「しない」→「する」に変わった）。
→ 負の対照：`tests/corrupt_H_trandel.asc` / `corrupt_I_icdel.asc`（+ `tests/directive_test.cir`）

**③ に伴う挙動の変化（隠さず書く）**：`--check` の入力に
**ラウンドトリップ生成物（`*_rt.cir`）を渡すと FAIL するようになった。**
`asc2ngspice.py` は抽出時に `.param pi=3.14159265358979` と収束補助の `.options` を
足すので、rt デッキには `.asc` に無いカードが 2 枚ある。それを正しく報告している
（図の欠陥ではなく「rt デッキは元のネットリストではない」という指摘）。
**`--check` には元のネットリストを渡すこと。** 実測: `audit_fable3/t_a2/base_rt.cir`
`d_test.cir` を入力にした 14 通りが `PASS → FAIL` に変わった。
なお `.TRAN` と `.tran` の大小文字違いは**誤検出だったので潰した**
（SPICE のディレクティブ名は大小文字を区別しない。先頭のキーワードだけ小文字化して比較する）。

## v1.2.0 — 2026-09-04

### 独立監査（2回目）で見つかった穴

**① たった1本のネットを一貫改名しただけで素通りした**

`sw` の FLAG 2枚を `swzz` に書き換えるだけで `VERIFY: PASS` / exit 0。
照合はネット名の**全単射**なので、改名そのものは（設計通り）無視される。
問題は、シンボルの無い素子（B/E/G/F/H）が TEXT ディレクティブとして
`v(sw)` のように**ネットを名前で**参照していること。図の側で `sw` が消えれば
その参照は宙に浮き、**LTspice では別物・壊れた回路になる。**

それ以前の文書には盲点として「**全ネットの一律リネーム**」とだけ書いていた。
**過小評価だった。**「1本でも、一貫していれば通る」が正しい。

→ ディレクティブ／TEXT 行の中の `v(ネット)` `i(素子)` `@素子[..]` を図と照合するようにした。
→ `tests/corrupt_D_netrename.asc` を負の対照実験に追加。

**② `.asy` の `PINATTR SpiceOrder` を一度も読んでいなかった**

`load_asy()` は `PIN` 行の**ファイル順**を使い、それが SpiceOrder と等しいと**仮定**していた。
同梱の10シンボルはたまたま一致しているので実害は出ていなかった。

しかし、ファイル順と SpiceOrder が食い違う `.asy` は**LTspice 的に合法**であり、
その場合の旧実装は**生成側と抽出側が同じ間違いをする**ため、
電源やダイオードの極性が全部逆でも**ラウンドトリップは PASS した。**

→ `SpiceOrder` を実際に読むようにした。無ければファイル順に落として **NOTE**、
   食い違えば **WARNING** を出したうえで SpiceOrder を採る。

> **記録**：この穴は、`SKILL.md` に「`SpiceOrder` がネットリストの端子順を決める」と
> 書いた**当日**に発覚した。LTspice の仕様としては正しい記述だったが、
> **このツールの実装としては正しくなかった。**
> 書いた本人（アシスタント）が、コードと突き合わせずに書いていた。
> ——**「仕様として正しい」は「実装がそうなっている」の証拠にならない。**

**検査を素通りする改竄が3種類見つかった：**

- **線分の途中に FLAG を貼る** → `sw`–`vout` が短絡するのに PASS
- **T字接続**（配線の端点が別配線の中間に着地）→ 同じく短絡するのに PASS
- **素子値の改変**（`{L}` → `1e9`）→ PASS（値を一度も比較していなかった）

原因は2つ：

1. `check_only()` が `geometric_check()` を**一度も呼んでいなかった**
2. ラウンドトリップの「権威」だった `asc2ngspice.py` が、
   LTspice の接触規則を**安全網より少ししか実装していなかった**（T字接続を見ていなかった）

→ 「権威」という表現を撤回。どのクラスの誤りを検出でき、どれができないかを
   16クラスの表として `NET2ASC.md` に明記した。
→ 3種類とも塞ぎ、`tests/corrupt_A/B/C` として残した。

**あわせて見つかったもの：**

- **ネット名の大文字小文字。** ngspice は `N1` と `n1` を同一視するが、ツールは別ネットとして
  扱い、**2つの分離した島として描画したうえで PASS を返していた**
- 自動命名 `n1, n2, …` が実在ネット名との衝突を検査していなかった。
  ngspice はノード名の大小文字を区別しないため、`N1` を持つデックでは**黙って短絡**しうる

### この修正で既存の抽出結果が変わった（重要）

同名 FLAG を結合するようにした結果、手描き `.asc` 6件中5件で

```
旧: S1 A n6 gateP1 gateN1 SW
新: S1 A n6 gateP1 0      SW
```

と変化した。これは**本物の見落としていた接続**で、`gateN1` は実際に接地されていた。
**数値は1つも動かなかった**ことを実測で確認（動作点が表示7桁すべて一致）。
